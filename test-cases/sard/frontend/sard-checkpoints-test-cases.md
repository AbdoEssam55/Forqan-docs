## Scope
- Tenant sard plan settings (checkpoints per hifz direction, default plan, committee, own-halaqa option).
- Sard sessions (create with auto scope, committee teachers, statuses, attempts).
- Committee sard evaluation (surah-by-surah marking, draft resume, submit).
- Memorization gate at pending checkpoints.
- Admin decision (pass/fail, grade, prize points), notifications, certificate.

## Test pages
- `/{tenantSlug}/settings/sard-plan`
- `/{tenantSlug}/sard`
- `/{tenantSlug}/sard/{sardSessionId}/evaluate`
- `/{tenantSlug}/sard/{sardSessionId}/review`
- `/{tenantSlug}/students/{studentId}`

## Test scenarios
- Admin configures the sard plan and committee; the system gates memorization at each checkpoint until the student passes a sard over the segment since the previous checkpoint.
- Committee evaluates surah by surah over multiple sittings; admin records the decision; pass unlocks the next stage, awards points, and issues a certificate.

## Delivery waves
- Wave 1 — Sard plan settings (`ALFQ-SARD-PLAN-001…007`)
- Wave 2 — Committee and sessions (`ALFQ-SARD-SES-001…007`)
- Wave 3 — Sard evaluation (`ALFQ-SARD-EVA-001…010`)
- Wave 4 — Checkpoint gate (`ALFQ-SARD-GATE-001…012`)
- Wave 5 — Decision, points, notifications (`ALFQ-SARD-DEC-001…005`)
- Wave 6 — Certificate (`ALFQ-SARD-CERT-001…002`)
